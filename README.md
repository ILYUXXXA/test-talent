# TalentHub

**TalentHub** — веб-платформа, которая объединяет школьников, родителей, школы и компании вокруг образовательных возможностей. Платформа помогает находить олимпиады, конкурсы и проектные мероприятия, подавать и обрабатывать заявки, отслеживать результаты и выстраивать партнёрства между образовательными учреждениями и организациями.

Приложение находится в каталоге `talenthub/`. Это клиентская часть TalentHub на React, которая взаимодействует с REST API.

## Возможности

TalentHub предоставляет единую среду для поиска образовательных мероприятий и взаимодействия участников образовательного процесса.

### Каталог мероприятий

- Просмотр доступных образовательных мероприятий.
- Поиск и фильтрация по названию, категории и интересам.
- Просмотр подробной информации об организаторе, датах, формате, месте проведения и условиях участия.
- Отображение доступных мест и сроков регистрации.
- Получение рекомендаций на основе интересов пользователя.

### Участие школьников

- Регистрация и вход в аккаунт.
- Заполнение профиля: школа, класс, город и интересы.
- Подача заявок на мероприятия.
- Просмотр статусов заявок и истории участия.
- Отмена заявки, если это допускается текущим статусом и правилами API.
- Просмотр посещений и подтверждённых достижений.
- Получение уведомлений и отметка уведомлений как прочитанных.

### Семейный кабинет

- Регистрация и вход родителя.
- Создание семейного приглашения и управление ссылкой приглашения.
- Присоединение ребёнка к семейному пространству по приглашению.
- Просмотр связанных детских профилей.
- Переключение между профилями детей.
- Просмотр образовательной активности ребёнка.
- Просмотр мероприятий и рекомендаций для выбранного ребёнка.
- Отправка ребёнку предложений об участии в мероприятиях.

### Кабинет школы

- Просмотр панели показателей школы.
- Создание и управление образовательными мероприятиями.
- Просмотр заявок участников.
- Работа со списком учеников и их активностью.
- Отметка посещения и обработка заявок.
- Поиск партнёров и работа с партнёрскими запросами.

### Кабинет компании

- Управление образовательными инициативами и мероприятиями.
- Просмотр заявок и информации об участниках.
- Создание адресных и открытых партнёрских запросов.
- Просмотр входящих предложений и откликов.
- Принятие решений по партнёрским взаимодействиям.
- Просмотр статистики и истории сотрудничества.

### Кабинет модератора

- Проверка мероприятий перед публикацией.
- Модерация партнёрских запросов.
- Проверка достижений учеников.
- Подтверждение или отклонение материалов.
- Управление аккаунтами организаций и выпуском токенов доступа.

## Роли пользователей

В приложении предусмотрены пять ролей:

| Роль | Назначение | Основной раздел |
|---|---|---|
| `student` | Школьник: профиль, каталог, заявки, достижения | Кабинет ученика |
| `parent` | Родитель: дети, прогресс и рекомендации | Семейный кабинет |
| `school` | Представитель школы: мероприятия, ученики и партнёры | Кабинет школы |
| `company` | Представитель компании: инициативы и партнёрства | Кабинет компании |
| `moderator` | Модерация платформы и аккаунтов организаций | Панель модератора |

Доступ к защищённым разделам определяется ролью текущего пользователя. При отсутствии авторизации пользователь перенаправляется на страницу входа. Для ученика также учитывается завершённость профиля.

## Технологии

### Клиентская часть

- **React 19** — построение пользовательского интерфейса.
- **React DOM 19** — отображение приложения в браузере.
- **React Router 7** — маршрутизация и защита разделов по ролям.
- **Vite 8** — локальный сервер разработки и production-сборка.
- **Radix UI** — доступные примитивы интерфейса, в том числе диалоги.
- **Lucide React** — набор иконок.
- **CSS** — стили, дизайн-токены, адаптивная раскладка и оформление страниц.

### Серверная часть

Клиент взаимодействует с REST API по HTTP. Запросы централизованы в модуле `src/api/client.js`. По умолчанию используется API:

```text
https://lbsuhack.onrender.com/api/v1
```

Адрес сервера можно переопределить переменной окружения `VITE_API_URL`.

## Запуск локально

Все команды выполняются из корня репозитория.

### 1. Перейти в каталог приложения

```bash
cd talenthub
```

### 2. Установить зависимости

```bash
npm ci
```

Если зависимости устанавливаются впервые и lock-файл ещё не используется:

```bash
npm install
```

### 3. Настроить API

Скопируйте пример переменных окружения:

**Windows PowerShell:**

```powershell
Copy-Item .env.example .env
```

**Linux / macOS:**

```bash
cp .env.example .env
```

При необходимости измените `VITE_API_URL` в файле `.env`.

### 4. Запустить сервер разработки

```bash
npm run dev
```

Vite запускает приложение на порту **5173**. Локальный адрес:

```text
http://localhost:5173
```

Сервер разработки поддерживает обновление страницы при изменении исходного кода.

## Переменные окружения

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `VITE_API_URL` | Базовый адрес REST API | `https://lbsuhack.onrender.com` |

Пример файла `.env`:

```env
VITE_API_URL=https://lbsuhack.onrender.com
```

Клиент автоматически добавляет префикс `/api/v1`. Поэтому допустимо указывать базовый адрес сервера как с этим суффиксом, так и без него.

Переменные с префиксом `VITE_` доступны в клиентском коде и попадают в браузерную сборку. В них нельзя хранить приватные ключи, пароли, секреты или серверные токены.

## Работа с API

Клиент использует REST API с базовым префиксом `/api/v1`. HTTP-запросы выполняются через функцию `request` из `src/api/client.js`.

### Авторизация

- Вход пользователя: `POST /auth/login`.
- Вход организации по токену: `POST /auth/organization-login`.
- Регистрация: `POST /auth/register`.
- Получение текущего пользователя: `GET /auth/me`.
- Для авторизованных запросов используется заголовок `Authorization: Bearer <token>`.
- Токен хранится в `sessionStorage` браузера под ключом `talenthub_access_token`.
- При ответе `401 Unauthorized` текущая сессия сбрасывается.

### Основные группы API-операций

**Справочники и мероприятия**

- `GET /reference-data`
- `GET /organizations`
- `GET /events`
- `GET /events?upcoming=true`
- `GET /events/{event_id}`
- `POST /events`
- `POST /events/{event_id}/registrations`

**Профиль и участие ученика**

- `GET /students/me`
- `PATCH /students/me`
- `GET /registrations/me`
- `POST /registrations/{registration_id}/cancel`
- `GET /students/me/success`
- `GET /recommendations`
- `GET /notifications/me`
- `PUT /notifications/{notification_id}/read`

**Семейный кабинет**

- `GET /parents/me/child`
- `GET /parents/me/children`
- `PUT /parents/me/children/{child_id}/select`
- `GET /parents/me/invitation`
- `POST /parents/me/invitation`
- `DELETE /parents/me/invitation`
- `POST /family-invitations/accept`
- `GET /parents/me/suggestions`
- `POST /parents/me/children/{child_id}/suggestions`
- `GET /parents/me/children/{child_id}/recommendations`

**Школы и компании**

- `GET /organizations/me/dashboard`
- `GET /organizations/me/events`
- `GET /organizations/me/students`
- `GET /partnership-requests?view=mine`
- `GET /partnership-requests?view=marketplace`
- `POST /partnership-requests`
- `POST /partnership-requests/{request_id}/responses`
- `PATCH /partnership-requests/{request_id}/decision`
- `PATCH /partnership-responses/{response_id}/decision`

**Модерация**

- `GET /moderation/queue`
- `POST /moderation/{resource}/{id}/decision`
- `GET /moderation/organization-accounts`
- `POST /moderation/organization-accounts`
- `POST /moderation/organization-accounts/{id}/token`

Перечень отражает API-вызовы, используемые клиентским кодом. Формат полей запросов и ответов определяется серверным контрактом.

### Обработка запросов

API-клиент:

- сериализует JSON-тела запросов;
- добавляет токен авторизации, когда он необходим;
- поддерживает передачу `AbortSignal` для отмены запросов;
- использует тайм-аут запроса 90 секунд;
- преобразует сетевые ошибки и ответы API в единый класс `ApiError`;
- обрабатывает истечение авторизации;
- нормализует адрес API, добавляя `/api/v1`.

### Состояние приложения

Модуль `src/data/store.js` централизует загрузку данных и операции изменения. Компоненты подписываются на обновления состояния через хуки из `src/data/hooks.js`. После успешных изменений данных выполняется обновление состояния с сервера.

## Архитектура клиентского приложения

Приложение построено вокруг следующих уровней:

1. **Точка входа.** `main.jsx` подключает глобальные стили и монтирует React-приложение.
2. **Маршрутизация.** `App.jsx` описывает URL и связывает их со страницами.
3. **Контроль доступа.** Компоненты `ApiBoundary`, `RequireRole` и `CatalogGuard` отвечают за загрузку начальных данных и ограничения доступа.
4. **Работа с данными.** `store.js` управляет состоянием и выполняет бизнес-операции.
5. **Сетевой слой.** `api/client.js` отвечает за HTTP, авторизацию и ошибки.
6. **Представление данных.** `normalizers.js` преобразует серверные сущности в удобный для интерфейса формат.
7. **Пользовательский интерфейс.** Компоненты и страницы отображают данные и предоставляют действия для каждой роли.

## Разработка

### Добавление новой страницы

1. Создайте компонент страницы в `src/pages/`.
2. Вынесите повторно используемые элементы в `src/components/`.
3. Добавьте маршрут в `src/App.jsx`.
4. Для закрытых разделов используйте `RequireRole` с нужной ролью.
5. Для работы с сервером добавьте операции в `src/data/store.js` и используйте общий API-клиент.
6. При необходимости добавьте преобразование ответа в `src/data/normalizers.js`.
7. Добавьте или обновите тесты в `tests/unit/`.

### Стили

- Глобальные дизайн-токены находятся в `src/styles/tokens.css`.
- Базовые стили — в `src/styles/base.css`.
- Общие и обновлённые стили интерфейса — в остальных файлах каталога `src/styles/`.
- Стили отдельных страниц и компонентов подключаются непосредственно в соответствующих модулях.

### Рекомендации по работе с кодом

- Используйте общий API-клиент вместо прямых несогласованных вызовов `fetch`.
- Сохраняйте единый формат ошибок через `ApiError`.
- Не размещайте приватные данные и секреты в переменных `VITE_*`.
- Проверяйте доступ к защищённым страницам для каждой роли.
- После изменений запускайте тесты и production-сборку.
